# FlowGram 节点面板与组件设计

状态：界面与组件设计准则。节点面板包含节点库、画布节点摘要、右侧配置面板和复杂字段的展开编辑。节点配置范围沿用 [节点配置设计](workflow-node-configuration.md)，本设计统一其界面与组件组织，不改变独立 Rust 后端的边界。

当前实现已将现有 15 类公开节点及循环内部节点接入统一面板，提供配置、输出、测试页签、同会话展开编辑、分类搜索节点库及共享取值、变量选择、映射、Schema、条件编辑器。Rust 单节点测试复用正式执行器，并通过 `test_node` Workflow Tool 暴露；测试快照、取消、超时和配置变化提示已接入。下文包含目标能力：尚无执行器的节点与编辑器不会作为可用入口展示，表达式、运行到此处、代码与列映射等仍属于目标设计。

## 视觉与布局

采用 [桌面设计规范](desktop-design-system.md) 中的 Claude 参考、表面、字体、圆角与动效。默认使用中性主按钮、轻边框和连续表单，类型颜色只放在小面积图标上。界面标签使用人能理解的名称，字段 ID 仅在复制引用或高级详情中展示。

目前配置面板中，参数名可以直接修改、每个字段单独包卡片、引用需要分别选择节点和输入路径，导致层级重复和操作负担。新面板由固定的字段标签、可绑定值输入框和轻量分组构成。节点名称在顶部直接编辑，不占用一个重复的表单区。

| 部位 | 设计 |
| --- | --- |
| 右侧面板 | 默认 400px，可在 320–520px 调整；受工作区可用空间约束，不挤压画布到不可操作 |
| 标题区 | 32px 类型图标、节点名称、类型说明；展开编辑、更多、关闭三个动作；节点 ID 在更多详情内 |
| 一级导航 | 配置、输出、测试三个页签；运行设置位于配置页末尾，默认折叠 |
| 内容 | 左右 20px，分组间距 24px，字段间距 16px；使用标题、留白和分隔线建立层级 |
| 表单 | 标签 13px/500，值 14px/400，说明 12px；常规控件高 36px，紧凑表格行 32px，图标按钮 28px |
| 底部操作 | 草稿保存状态和一个“测试节点”主按钮；移除整条宽度的应用按钮，关闭面板不丢草稿 |
| 边框与表面 | 普通字段不套卡片；输入框 8px 圆角，组合编辑器共享一个外边界；轻底色用于只读摘要和结构化内容 |
| 窄空间 | 保留字段标签和值，Key Value 表改为上下排布；复杂 Schema、提示词和代码提供展开入口 |

调整宽度直接跟随指针，不做尺寸动画。工作区不足以容纳最小面板和可用画布时，使用用户可返回的展开编辑视图，不继续缩小表单字体。当前方案针对桌面主工作区，不以移动端页面替代桌面交互。

### 配置页

顺序为资源、主要输入、操作参数、可选配置、运行设置；没有资源的节点自然省略对应区域。默认可见内容由操作决定，避免显示与当前操作无关的字段。

字段行结构为“标签与必要提示 → 值输入 → 按需说明或错误”。必填标记使用文字或小星号，不用红色制造错误状态。说明默认只显示最有帮助的一句；复杂规则放在带标签的帮助入口中。

每个可绑定字段都用 Value Editor。固定文本直接输入；引用变量显示来源和字段的单个标签，如“输入 / url”；表达式使用 fx 标记；文本模板内显示变量片段。取值方式在同一入口切换，避免每个参数先放一个完整的来源下拉框。

变量选择使用锚定弹层。顶部搜索，下方按“入口输入、上游节点、当前循环、运行上下文”分组；每项显示名称、类型和样本，选中后原地形成引用。复杂路径提供树形展开和路径编辑，默认无需手输节点 ID。

资源字段使用 Resource Picker，显示图标、名称和连接状态。创建连接进入完整资源设置，返回后恢复字段焦点。秘密值始终引用，不回填为普通字符串。

### 输出页

输出字段树显示名称、类型、可空性、描述和最近样本。操作切换会更新输出 Schema，受影响的下游引用集中展示诊断。用户可以复制引用，不能在只读输出树里随意修改由执行器决定的字段。

需要用户声明输出的节点，如结构化生成和代码执行，配置页提供 Schema Editor；输出页展示其生效结果。这样声明输入和查阅输出使用同一份数据，不出现两套独立字段定义。

### 测试页

测试页分为测试输入和最近结果。输入来源可选手工样本或选定运行快照，标明来源与配置版本。测试节点只执行当前节点，执行上游是单独的“运行到此处”动作。

结果按输入解析值、业务输出、过程和诊断呈现，文件、表格、文档和工具调用使用共享结果组件。状态包括尚未测试、运行中、成功、失败、等待输入、等待授权、已取消和来自旧配置；成功与等待均采用中性状态文字和图标，失败使用错误色。

修改配置后保留旧结果，标记其配置版本，不把旧结果当成当前验证。测试中可以停止；停止与重新测试位置固定。非幂等动作的未知结果单独标记为待核实，不能自动提示重试为安全。

### 展开编辑

从面板右上角或复杂字段展开，打开同一工作区内的宽视图，保留左侧精简节点导航、中间编辑内容和右侧输出参考。它使用同一个表单会话；展开和返回不复制节点数据、不重新挂载画布、不创建新草稿。

提示词、Schema、代码、表格映射可展开对应字段，其他配置仍可通过节点导航到达。返回键回到原节点、原页签、原滚动位置和原焦点。

### 节点库

节点库采用搜索与紧凑列表。按数据处理、流程控制、模型与 Agent、文件文档、网络工具、数据库存储、触发交互分类；常用和最近是用户自己的快捷入口。每项包含类型图标、名称和一句用途说明，不使用大面积彩色卡片。

搜索同时覆盖名称、别名和具体操作，例如“去空格”能找到文本处理并预选对应操作。“MCP 工具”进入连接和动作选择；动态工具可搜索，但不会把每个服务器、供应商或模型当作新的基础类型。

从已有端口添加节点时，可以使用当前输出类型筛选兼容节点；不兼容项显示原因而不是静默消失。选择节点后插入画布并选中其首个必填字段，不弹出第二层配置对话框。

## 组件分层

组件按稳定职责组织。底层控件不判断节点类型；组合编辑器只认识数据形态和能力；节点通过注册定义提供字段与布局。原子组件的价值在于共享交互、状态和语义，不能只共享一层颜色。

| 层次 | 内容 | 允许依赖 |
| --- | --- | --- |
| 设计 Token | 表面、文字、边框、圆角、间距、控件高度、动效、层级 | 桌面主题和无障碍设置 |
| 基础控件 | Button、IconButton、Input、Textarea、NumberInput、Select、Combobox、Switch、Tabs、Disclosure、Popover、Tooltip、Separator | Token 与基础交互库 |
| 字段与取值 | FormField、FieldLabel、FieldHint、FieldError、FormSection、RepeatableRows、ValueEditor、VariablePicker、ResourcePicker | 基础控件、表单状态和变量服务 |
| 组合编辑器 | MappingEditor、ConditionBuilder、SchemaEditor、KeyValueEditor、PromptEditor、CodeEditor、ToolSetEditor、ColumnMapper | 字段与取值、编辑器与资源适配器 |
| 面板容器 | NodeInspector、OutputInspector、NodeTestPanel、ExpandedEditor、NodeLibrary | 注册表、表单会话、结果与运行服务 |

状态、表单控制器、变量推导和异步资源加载属于无视觉的逻辑层，组件通过适配器读取，不把 API 调用散落到各个输入框中。Rust 负责执行和权威校验，前端逻辑层负责草稿、呈现和即时反馈。

### 基础控件

| 组件 | 统一规则 |
| --- | --- |
| Button 与 IconButton | 明确 primary/secondary/ghost/danger、尺寸、加载和禁用状态；主动作每个区域只有一个 |
| Input 与 Textarea | 有标签、占位、只读、无效和加载态；不会因输入失败重置内容；单行与多行共享边框和焦点样式 |
| NumberInput 与 UnitInput | 空值与 0 区分；单位有独立位置；支持上下界和步长，不自动夹到最近合法值 |
| Select 与 Combobox | 静态短枚举用 Select，大量或异步候选用 Combobox；共享键盘、空结果、加载与重试反馈 |
| Popover 与 Tooltip | 层级、定位、焦点恢复和 Escape 关闭一致；关键说明不能只在悬停时出现 |
| Tabs 与 Disclosure | 页签切换保留内容会话；折叠区域显示简短有效配置摘要，不用“高级”掩盖必填项 |
| TypeBadge 与 StatusLabel | 类型是小面积标记，状态有图标和文字；不用颜色单独传达含义 |

### 字段和取值组件

| 组件 | 责任 | 不承担的责任 |
| --- | --- | --- |
| FormField | label、required、description、error、可访问关系与一致间距 | 节点执行、资源查询或节点类型判断 |
| FormSection | 标题、说明、可选折叠、折叠摘要 | 把每个字段重新包成一张卡片 |
| RepeatableRows | 稳定行 ID、增删、排序、焦点和逐行错误 | 具体业务字段含义 |
| ValueEditor | 固定值/引用/模板/表达式的统一入口，按 Schema 选择内层编辑器 | 自己发起工具调用或推断授权 |
| VariablePicker 与 VariableChip | 合法作用域、字段树、搜索、类型、样本和引用展示 | 把不可达变量伪装成可用选项 |
| ExpressionEditor 与 TemplateEditor | 语法提示、变量插入、预览和本地未完成输入 | 修改后端求值规则或执行任意脚本 |
| ResourcePicker | 资源类型、能力筛选、状态、切换影响和设置返回位置 | 保管明文凭证或对不同节点使用不同的连接存储 |
| PathPicker 与 RangeEditor | 字段路径、查询形态、页码/区间/索引单位 | 隐式类型转换和无限范围执行 |

ValueEditor 的值模式与编辑器类型正交。比如 string 字段可用单行、多行或提示词编辑，但引用值始终使用相同的引用结构；FileRef 固定值使用文件选择器，引用值仍使用 VariablePicker。切换值模式保留各模式的本地草稿，执行定义只保存当前生效值。

### 组合编辑器

| 编辑器 | 共享结构 | 覆盖节点 |
| --- | --- | --- |
| MappingEditor | 目标路径、类型、取值、默认值、稳定行 ID | 字段映射、子工作流输入、返回结果、结构化写入、MCP 参数预绑定 |
| KeyValueEditor | 键、ValueEditor、启用状态、删除；宽度不足时上下排列 | HTTP Query/Header、元数据、环境变量引用 |
| ConditionBuilder | AND/OR 组、左右值、类型化运算符、嵌套和逐条件校验 | If、Switch、列表过滤、事件匹配、循环退出、数据库条件 |
| SchemaEditor | 字段树、类型、必填/可空、约束、JSON 视图与差异提示 | 入口表单、结构化生成、代码输出、数据校验、工具契约查看 |
| PromptEditor | 消息、文本块、变量片段、附件、展开编辑 | 模型生成、提取、分类、Agent、图像和语音提示 |
| CodeEditor | 语言适配、语法诊断、变量插入、展开、独立编辑缓冲 | 表达式、JSON、SQL、隔离执行代码；各语言权限由执行资源决定 |
| ToolSetEditor | 工具发现、资源绑定、参数预绑定、权限摘要、契约差异 | Agent 工具集、子工作流工具与 MCP 动作选择 |
| ColumnMapper | 列来源、类型、顺序、格式、样本和映射 | CSV、Excel、SQL、表格输出、向量索引字段 |
| OrderedRuleEditor | 条目 ID、名称、顺序、条件或说明、端口引用 | Switch 规则、分类项、审批动作、并行分支；领域内容作为行槽位 |
| ScheduleEditor | 时区、频率、日期区间、表达式和后续触发预览 | 定时触发与时间计划；后端负责实际调度 |
| LocatorEditor | 定位方式、角色/名称/属性、多个匹配策略和样本 | 浏览器操作和未来的 UI 自动化工具；不自己持有浏览器连接 |
| ResultViewer | 字段树、列表、文件、文档、消息、工具轨迹和来源版本 | 节点测试、工作流执行详情、Agent 工具结果 |

SchemaEditor 复用字段树和基础类型编辑器，但表单展示属性与执行 Schema 分开管理；占位文字、控件类型、分组、可见性不进入业务输出数据。组合编辑器允许领域槽位，槽位只能提供字段定义、行内容或格式化器，不能再创建一套面板壳和保存逻辑。

### 节点组合实例

| 节点 | 组件组合 |
| --- | --- |
| HTTP 请求 | ResourcePicker + Select 与 ValueEditor 的请求地址行 + KeyValueEditor + 正文对应的 MappingEditor/CodeEditor + 公共运行设置 |
| 列表过滤 | 数组 ValueEditor + ConditionBuilder + 公共运行设置；测试结果使用表格 ResultViewer |
| 结构化生成 | 模型 ResourcePicker + PromptEditor + SchemaEditor；输出页复用同一 Schema 的只读视图 |
| Agent | 模型 ResourcePicker + PromptEditor + ToolSetEditor + 输出要求字段 + 预算字段；过程使用共享工具轨迹 |
| MCP 调用 | ResourcePicker + 工具 Combobox + 按工具 Schema 生成的 FormField/ValueEditor；不为每个工具增加组件文件 |
| CSV 与 Excel | 文件 ValueEditor + 操作 Select + ColumnMapper + 格式字段；工作表列表用 RepeatableRows |
| 分支与循环 | ValueEditor + ConditionBuilder/OrderedRuleEditor + SchemaEditor；端口和作用域由图契约提供 |
| 人工输入 | PromptEditor + SchemaEditor 与表单展示属性 + 等待期限字段；运行中的表单用相同字段注册表呈现 |

每个编辑器接受值、Schema、可绑定能力、只读/禁用状态、字段诊断和统一的变更回调；请求展开、定位错误和选择资源通过容器服务完成。动态候选查询与值变更分离，依赖关系形成有向图；修改来源字段只刷新受影响候选与诊断，避免跨字段 effect 相互写入形成循环。

## 注册定义与表单会话

一个节点注册定义包含执行契约和 UI 描述两个部分。执行契约由后端提供；UI 描述引用已注册编辑器和字段路径。界面不靠节点名推断字段，不由前端任意改变输入输出语义。

| 定义 | 内容 |
| --- | --- |
| 节点元信息 | 稳定类型 ID、版本、名称、描述、分类、图标、搜索别名、操作目录 |
| 输入 Schema | 类型、必填、枚举、约束、默认值、允许的绑定方式 |
| 输出契约 | 固定或按操作推导的 Schema、字段描述、端口及作用域约束 |
| 资源需求 | 资源类型、能力要求、权限与副作用声明 |
| UI 布局 | 分组顺序、字段路径、编辑器 ID、标签、帮助、条件显示、折叠摘要 |
| 动态候选 | 已声明的资源查询类型、依赖字段、分页和错误行为；不把任意地址或脚本作为表单扩展 |
| 运行设置 | 支持的超时、重试、取消、恢复、测试方式 |

条件显示使用有限的数据规则，如字段等于、包含、存在与 AND/OR；不能在注册定义里注入任意前端代码。内置字段值校验和结构校验共用后端契约，前端补充交互反馈。资源能力异步返回时，用请求身份和资源版本丢弃过期响应，避免旧模型的字段覆盖新选择。

一个 FormSession 按工作流、节点与基准修订创建，保存合法草稿、编辑器暂存文本、字段错误、展开状态、焦点恢复信息和测试结果引用。配置页、输出页、测试页和展开编辑共用会话；节点切换不复制独立 JSON 镜像。

弹层的打开状态、搜索词和焦点属于局部交互状态。保存回执或相同状态的回传不能触发表单重建，也不能关闭正在选择的变量。每次测试绑定节点 ID、配置修订和测试执行 ID；节点切换、重新测试或停止后，晚到的旧结果只归档到原执行，不能覆盖当前面板。

字段编辑先更新本地会话，合法的变更合并进工作流草稿，再按既有修订协议保存。输入尚不完整时保留文本，不写入无效的执行定义；关闭面板、切换页签和展开编辑不清空暂存。顶部保存状态区分正在保存、已保存、含未完成字段、保存失败和修订冲突。

固定字段名称由注册表决定，用户只能改显示名称。只有 Mapping、Key Value、Schema 等明确允许动态键的编辑器提供“添加字段”入口，不给所有节点暴露通用的任意参数增删。

## 现有能力复用

仓库已具备表单与变量基础，桌面应用应复用其模型和服务，通过桌面适配层呈现。避免为了新视觉改动所有公开材料或扩宽共享库版本要求。

| 现有位置 | 复用方向 | 需要核实的边界 |
| --- | --- | --- |
| `packages/node-engine/form-core` | 字段状态、校验、可见性和 React 表单能力 | 与桌面草稿、修订和 Rust 诊断的桥接方式 |
| `packages/variable-engine/variable-core` 与 `variable-layout` | 作用域、变量声明、类型和画布引用关系 | 以 Rust 权威执行语义校正可达性，不以任意祖先节点都可引用代替作用域 |
| `packages/materials/form-materials` | 已有 FlowValue 类型、变量效果、Schema、条件和编辑器扩展的设计与可拆逻辑 | 现有视觉绑定 Semi UI，开发依赖 React 18；不能假定其完整 UI 可直接混入 React 19 桌面界面 |
| `packages/variable-engine/json-schema` | 基础类型与字段结构工具 | 扩展类型和后端支持的 Schema 子集需一致 |
| `desktop/src/components/ui` | 现有 Button、Input 等桌面控件继续统一 | 按设计补齐状态与控件能力，避免再引入第二套视觉体系 |
| `desktop/src/components/resizable-panel.tsx` | 有界拖拽、键盘调整、持久化 | 更新节点面板尺寸并保留工作区剩余宽度约束 |

新桌面组件先放在现有桌面项目的 `ui`、`form`、`editors`、`node-inspector` 和 `node-library` 模块内。形成独立发布需求后再决定包边界。已有编辑器的纯逻辑可通过适配器复用；不能为复用一个输入框整包引入另一套视觉主题。

### 防止特化扩散的规则

1. 新节点先用已有字段和编辑器组合；节点目录里增加 Schema、默认值、布局和执行器，不增加独立面板。
2. 碰到新数据形态时，为该形态注册编辑器，并明确输入值、Schema、诊断、只读与禁用契约；编辑器可以服务多个动作和外部工具。
3. 基础控件和字段层不读取 node kind；节点专属的差异保留在注册定义或小型领域槽位中。
4. 所有编辑器复用 Field、ValueEditor、RepeatableRows、错误定位、展开编辑、保存和测试机制。
5. 权限、执行校验和资源访问由后端统一处理；表单条件显示不是权限控制。
6. 引入新依赖前检查现有编辑器、React 兼容性与 Rush 约束；不能以某个节点的需求修改整个仓库的基础版本要求。

## 组件状态与验证矩阵

原子组件需要同时定义默认、hover、focus、disabled、readOnly、loading、invalid；组合编辑器还要定义空值、无候选、资源失效、类型冲突、超长内容和旧测试结果。状态示例与组件实现放在一起，节点示例只组合它们，不另写一次状态。

| 验证对象 | 必须看到的行为 |
| --- | --- |
| ValueEditor | 文本、数字、false、0、null、引用、模板和表达式保持类型；切换方式不丢草稿 |
| VariablePicker | 键盘搜索和选择、作用域过滤、字段类型、空结果、失效引用和焦点返回 |
| ResourcePicker | 加载、失效、切换、能力不足、无结果、新建后返回；过期响应不覆盖当前选择 |
| RepeatableRows | 增删重排后保持行身份、逐行错误和焦点；删除当前行后移动到合理位置 |
| Schema 与条件 | 嵌套结构、类型切换、动态字段、无效表达式、必填与隐藏冲突 |
| 保存和冲突 | 未完成输入保留、失败可恢复、远端修订冲突可定位；不在保存后重置视口 |
| 布局与动效 | 面板最小/默认/最大宽度、键盘调整、连续拖拽、展开往返；减少动态效果有效 |
| 测试生命周期 | 运行、成功、错误、等待、取消、结果待核实和旧配置提示；工具过程使用稳定身份 |

设计预览覆盖 HTTP、列表过滤、Agent 和结构化生成四种不同配置形态，并展示输出、测试、变量弹层、节点库和展开编辑。其用途是验证同一套组件能表达不同节点，不能代替 87 种节点实际执行器的实现和验收。
